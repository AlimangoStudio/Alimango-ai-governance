# Audit Kernel Contract

An audit kernel should receive immutable identifiers for the target revision, declared scope, requirements, changed surfaces, relevant policies, and evidence. It should not depend on the implementer's completion narrative.

Reviewer lanes inspect correctness, security/capability, context/provenance, supply chain, data/privacy, regression, performance/UI when relevant, and delivery claims.

Output: coverage, skipped surfaces, findings, severity, evidence, dispositions, and a deterministic verdict. Findings are appended/reconciled rather than silently erased.
