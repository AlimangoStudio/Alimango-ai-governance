# Spec Kit Workflow

Use for behavior-changing or control-changing work.

1. Inspect repository/spec state before numbering or assuming structure.
2. Specify the problem, scope, threats, requirements, capabilities, and acceptance evidence.
3. Plan architecture, blast radius, risk, tests, review, and rollback.
4. Decompose into independently checkable tasks.
5. Analyze contradictions, missing requirements, unsafe assumptions, and dependency gaps.
6. Build a checklist that tests the contract rather than restating it.
7. Implement the smallest coherent change.
8. Validate positive, negative, bypass, and regression paths.
9. Converge artifacts and findings.

A small change gets smaller artifacts, not an exemption.
