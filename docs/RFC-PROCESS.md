# RFC / Proposal Process

Use a proposal when a change introduces a new control family, changes authority semantics, changes risk/capability classification, introduces a dependency, or materially changes contributor/agent behavior.

A proposal should contain: failure mode, threat model, control design, alternatives, capability impact, context/data impact, bypass analysis, evidence plan, performance/maintenance cost, compatibility, and public/private adoption notes.

Discussion may converge on `accepted-for-lab`, `needs-experiment`, `rejected`, or `superseded`. `accepted-for-lab` is not production adoption.
