# RFC / Proposal Process

Use a proposal when a change introduces a new control family, changes authority semantics, changes risk/capability classification, introduces a dependency, or materially changes contributor/agent behavior.

A proposal should contain: failure mode, threat model, control design, alternatives, capability impact, context/data impact, bypass analysis, evidence plan, performance/maintenance cost, compatibility, public-scope implications, and migration notes when relevant.

Discussion may converge on `accepted-for-reference`, `needs-experiment`, `rejected`, or `superseded`. Acceptance means the design is part of this open reference project at the accepted revision; it is not a certification of every downstream use.
