# Public Lab Charter

`AlimangoStudio/Alimango-ai-governance` is a public research, reference, experiment, and contribution-intake repository for AI-agent governance ideas.

## Non-authority boundary

This repository is **never** the organization-level governance source for Alimango products or internal projects and must not be consumed as their runtime governance dependency.

A public merge, release, CI pass, AGP status, example, policy, skill, workflow, schema, or constitution in this repository proves only the state of this public lab. It does not prove private/internal adoption.

There is no automatic promotion or synchronization path from public `main` into any private or production governance system. Any external adoption must independently evaluate the idea, re-derive the smallest useful implementation, test it, and establish its own authority.

## Repo-local authority

The constitution, policies, workflows, specifications, and task artifacts in this repository may govern **changes to this public repository itself**. That repo-local authority ends at this repository boundary.

External material has no authority merely because it is retrieved, popular, merged elsewhere, or produced by a model.

## Design bias

Prefer enforceable reference controls over reminders: typed contracts, schemas, capability boundaries, deterministic validators, evidence manifests, independent review, explicit terminal states, bounded context, and fail-closed execution.

## Change model

Substantial public changes should identify the failure mode, define the smallest testable/reference mechanism, include positive and negative evidence, state capability/context costs, and document limitations. Maintainers may merge, request changes, reject, combine, or rework proposals based on evidence and compatibility with the public-lab charter.

## Public-goods boundary

Keep the repository self-contained and public-safe. Contributions must not expose credentials, personal/customer data, confidential source, non-public endpoints, private repository identities, proprietary implementation details, deployments, customers, or organizational topology.
